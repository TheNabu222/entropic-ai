How are windows managed?

The AnTiChRiSt KeTtLeKoRn project employs a windowing system that is a primary interaction model, meticulously designed to emulate a custom operating system desktop from around 2002. This "desktop metaphor" is crucial for establishing the nostalgic "Humongous Games feel" and a "chaotic, personalized workspace" that rejects modern, sterile web design.
Here's a breakdown of how windows are managed within this system:
1. Core Philosophy and Aesthetic:
• Desktop Metaphor: The entire application interface looks and feels like a custom OS desktop from around 2002, with content organized within distinct, bordered zones, often emulating a classic HTML frameset using modern CSS.
• No Modern Modals: The design explicitly states that "Nothing opens in a sleek, modern modal." Instead, "Everything opens in its own draggable, resizable, old-school OS-style window". This is fundamental to the "Humongous Games feel".
• Window "Chrome": Each window features a thick title bar, which can be a "garish blue" or a custom gradient, displaying the window's title in a pixel font.
    ◦ Control Buttons: The title bar includes the classic three buttons in the top right: a pixelated underscore for minimize, a square for maximize, and an "X" for close.
    ◦ Content Area: Window content is frequently displayed within an <iframe> or a div element with overflow: scroll; to achieve the "classic, chunky scrollbars".
2. Core Window Functionalities:
• Draggable: Windows are designed to be draggable. This functionality can be disabled on smaller screens or mobile devices. The dragging mechanism involves tracking mouse movements (pos1, pos2, pos3, pos4) and updating the window's top and left CSS properties.
• Resizable: Windows are resizable, allowing users to adjust their dimensions. Custom resizer handles (e.g., resizer-r, resizer-b, resizer-br) are used for this purpose.
• Overlapping: Multiple windows can be open simultaneously and overlap on the desktop, creating a "chaotic, personalized workspace". The zIndex property is used to manage which window appears on top.
• Minimize: Clicking the minimize button (_) hides the window from view by setting its display style to 'none', effectively "docking it to a taskbar at the bottom". The application remains active and accessible via the taskbar.
• Maximize: The maximize button (☐) toggles the window's state to fill the available main content area. When maximized, its width becomes 100% and height becomes calc(100% - var(--taskbar-height)). The system saves the previous size and position to restore them when un-maximized.
• Close: Clicking the close button (X) hides the window (setting display to 'none') and removes its corresponding button from the taskbar.
• Bring to Front/Activate: When a user clicks on a window, it is brought to the foreground and marked as the activeWindow. This is achieved by updating its zIndex to a higher value and adding an 'active' CSS class, while removing it from previously active windows.
• Taskbar Integration: A classic Windows 98/XP-style taskbar at the bottom of the screen displays a button for each open window for easy multitasking [1.4, 129, 219, 239, 266, 286, 287, 335, 336, 371, 372, 373, 414, 417, 448, 539, 621, 629, 641]. Clicking a taskbar item can restore a minimized window, bring a visible window to the front, or minimize an active one. The taskbar visually reflects the active window's state.
